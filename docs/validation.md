# Проверка версии 2.0

Дата: 10 ноября 2026 года. Результаты версии 1.0 сохранены отдельно:
[validation-1.0.md](validation-1.0.md).

- JDK 17.0.20.1+1, Gradle 8.11.1, AGP 8.9.2, Android SDK 35.
- `assembleDebug`, `assembleRelease`, `assembleDebugAndroidTest` завершились успешно.
- `testDebugUnitTest`: **55 тестов, 0 ошибок, 0 падений, 0 пропусков**.
  Из них 28 проверяют запись и исправление употребления, 21 — основные расчёты,
  6 — расписание уведомлений.
- `lintDebug`: 0 ошибок, 4 предупреждения (портретная ориентация,
  использование API и порядок параметра Modifier); 5 информационных замечаний.
- На отдельном программном эмуляторе Android 9 / API 28 выполнен весь
  инструментальный набор: **39 тестов, 0 ошибок, 0 пропусков** (183,662 с).
  Запуск: `adb -s emulator-5556 shell am instrument -w -r
  ru.daybyday.app.test/androidx.test.runner.AndroidJUnitRunner`.
- Проверены фактическая миграция схемы 1→2 с валидацией Room, ограничения
  внешних ключей и уникальности, транзакции репозитория, прежние уведомления,
  навигация, запись/отмена/исправление даты и видимость кнопки при шрифте 150%.
- Журнал Android и XML модульных результатов: [test-results/2.0](../test-results/2.0).
- Повторный `WITH_EMULATOR=1 bash scripts/setup-cloud.sh` завершился успешно.
  SDKManager использует доверенный системный Java truststore; проверки TLS
  и контрольных сумм инструментов включены.
- В выпускном APK `ru.daybyday.app`, `versionCode=2`, `versionName=2.0`,
  minSdk=28. Разрешение `INTERNET` отсутствует.

## Проверка обновления с заполненной историей

На отдельном эмуляторе установлена тестовая копия фактического APK 1.0.
После запуска добавлена синтетическая БД с сохранённой схемой и identity hash
версии 1: завершённый период 21 день (ID 11), текущий период 22 полных дня
(ID 42), пять наград с исходными датами и настройками DataStore.
Затем установлен компактный APK 2.0 через `adb install -r`, без удаления
приложения и без очистки его данных между версиями.

Сравнение снимков до/после подтвердило неизменность всех старых периодов,
наград, их дат и связей; настройки и состояние уведомлений сохранились
байт в байт. Room перешёл на схему 2; журнал употребления создан пустым,
проверка внешних ключей проходит.

В финальной R8-сборке через интерфейс выбраны «Вчера» и подтверждение.
Сохранены предыдущие 21 день, создан период с сегодняшнего дня:
0 полных дней и текущий день 1. Исходные пять наград и настройки сохранены.
Сообщение подтверждает сохранение результата без негативной оценки.
Исправление этой же отметки на «Сегодня» сохраняет её ID и связанные периоды,
переносит начало на завтра и оставляет 0 полных дней без подписи «день 1».
После повторного открытия результат сохранён; исходные награды и настройки
не изменились.
Снимки интерфейса: [screenshots/v2](screenshots/v2).
Снимки данных и результат сравнения: [test-results/2.0](../test-results/2.0).

Обе тестовые копии APK подписаны одним временным тестовым ключом.
Эта проверка подтверждает миграцию данных и работу выпускной сборки,
но не совместимость с оригинальной подписью установленного приложения 1.0.

## Подпись и доступные файлы

`scripts/package-test-apk.sh --unsigned` успешно создаёт компактную R8-сборку
`/workspace/artifacts/day-by-day-2.0-unsigned.apk`. Она не подписана и
не предназначена для установки на телефон.

Проверено отрицательное условие: обычный вызов скрипта с новым локальным
ключом завершается отказом из-за несовпадения сертификата с выпущенным APK 1.0.
Файл `day-by-day-2.0.apk` при этом не создаётся.

Исходный приватный keystore из прежней облачной среды не восстановлен.
Его нельзя получить из публичного сертификата или APK. Сертификат 1.0:
`37:D8:1A:1C:E0:C6:3E:E7:19:31:59:58:A7:85:D5:AF:48:8E:80:11:F5:F9:06:ED:FC:EC:EC:EC:34:EE:1B:06`.
Подписанное обновление для существующей установки остаётся заблокировано
до восстановления именно этого ключа. APK 1.0 и его архив исходников сохранены.

Проверка на физическом телефоне, совместимость подписи с установленной 1.0
и разрешение уведомлений на Android 13+ не считаются выполненными.
Старое приложение на телефоне удалять нельзя: история хранится локально.
