# Техническое задание
## Android-приложение «День за днём»

**Тип:** персональный трекер дней без алкоголя с геймификацией
**Платформа:** Android
**Формат:** устанавливаемое приложение APK
**Язык интерфейса:** русский
**Версия:** MVP 2.0 (расширение версии 1.0)
**Авторизация:** не требуется
**Интернет:** для основных функций не требуется

---

## 1. Концепция приложения

Создать мобильное приложение, которое помогает пользователю отслеживать количество дней без алкоголя и поддерживает мотивацию с помощью игровых механик.

Основной пользовательский сценарий:

1. Пользователь впервые запускает приложение.
2. Указывает дату начала периода без алкоголя.
3. Видит большой счётчик дней.
4. Получает достижения за определённые этапы.
5. Может изучать календарь, статистику и историю.
6. Получает необязательные мотивирующие уведомления.
7. Возвращается в приложение, чтобы видеть свой прогресс.

**Главный принцип:** позитивная мотивация, отсутствие осуждения и уважение к любому прогрессу.

## 2. Главный экран

Центральный элемент — большой анимированный счётчик.

### Элементы экрана

**Верхняя область:**
- Название приложения.
- Иконка настроек.
- Текущая дата.

**Центральная область:**
- Крупное число дней без алкоголя.
- Подпись «День без алкоголя» / «Дня без алкоголя» / «Дней без алкоголя» с правильным склонением.
- Подпись «Твой текущий период».
- Круговая шкала прогресса до ближайшей ачивки.
- Небольшая анимация при достижении очередного этапа.

**Ниже счётчика:**
- Текущий уровень.
- Название уровня.
- Прогресс до следующей награды.
- Карточка ближайшего достижения.

Пример:

**12 дней без алкоголя**

Уровень 3 · Набираешь темп

До следующей ачивки — 2 дня.

**Дополнительная статистика:**
- Лучший результат.
- Всего дней без алкоголя за всю историю.
- Получено достижений.

**Нижняя навигация:**
- Главная
- Достижения
- Календарь
- Статистика

## 3. Логика таймера

### Первоначальная настройка

При запуске пользователь выбирает дату первого дня без алкоголя.

Дата сохраняется локально.

### Правила подсчёта

Отображать два понятия:

- **Текущий день** — порядковый календарный день периода.
- **Полных дней** — количество завершённых календарных дней.

Пример: если первый день без алкоголя — 18 октября, то 18 октября отображается «День 1, полных дней: 0», а 19 октября — «День 2, полных дней: 1».

На главном экране крупно показывать количество полных дней, чтобы не преувеличивать продолжительность периода.

Счётчик обновляется автоматически при смене календарной даты, открытии приложения и возвращении из фонового режима.

Таймер не должен зависеть от того, открывал ли пользователь приложение каждый день.

### Редактирование даты

Дату начала периода без связанной отметки можно изменить через настройки с пересчётом статистики и достижений. Если начало связано с отметкой употребления, настройки открывают редактор даты этой отметки: начало следующего периода пересчитывается вместе с ней.

### Фиксация употребления и новый период в 2.0

На главном экране над нижней навигацией постоянно доступна второстепенная кнопка «Отметить употребление». Доступ к ней не зависит от прокрутки главного экрана.

При нажатии:
- Пользователь выбирает «Сегодня», «Вчера» или другую допустимую дату.
- До сохранения видит дату употребления, точный результат предыдущего периода и начало периода после отметки.
- До подтверждения реальные данные не изменяются.
- После подтверждения день употребления исключается из подтверждённых дней без алкоголя.
- Предыдущий результат сохраняется, следующий период начинается на следующий календарный день после употребления.
- Полученные достижения и исходные даты их получения сохраняются; статистика рассчитывается по сохранённым периодам.
- Пользователь получает нейтральное поддерживающее сообщение.

Если употребление было вчера, сегодня становится первым днём нового периода: текущий день 1, полных дней 0. Если употребление было сегодня, новый период начинается завтра: на счётчике 0 полных дней и явная подпись о будущей дате начала. Сегодня не показывается как первый трезвый день.

В «Настройки → История отметок» доступно изменение даты любой сохранённой отметки в допустимом диапазоне между соседними периодами. Коррекция меняет связанные границы периодов, сохраняя остальные записи. Дублирующиеся даты и пересечение соседних отметок запрещены. Удаление отдельных отметок не входит в объём 2.0.

Для первого дня периода и последовательных дней употребления допустимы внутренние нулевые периоды. Они не увеличивают число завершённых периодов, сумму дней и историю результатов. Прежние неизвестные промежутки не заполняются вымышленной активностью.

Обычное начало нового отсчёта сохраняет историю. Удаление всей истории — отдельное действие «Удалить все данные» в настройках с подтверждением.

Никаких отрицательных баллов, штрафов, сообщений «Ты сорвался», «Всё сначала» или «Серия потеряна». Пример: «Предыдущий результат — 21 день — сохранён в истории. Продолжаем день за днём».

## 4. Система достижений

Создать систему коллекционных ачивок с оригинальными иконками, названиями и анимацией разблокировки.

### Основные достижения

| Дней без алкоголя | Название достижения |
|---|---|
| 1 | Первый шаг |
| 3 | Отличное начало |
| 7 | Первая неделя |
| 14 | Две недели |
| 21 | Три недели |
| 30 | Первый месяц |
| 45 | Уверенный курс |
| 60 | Два месяца |
| 90 | Большая дистанция |
| 100 | Сотня |
| 180 | Полгода |
| 270 | Девять месяцев |
| 365 | Год |
| 500 | Пятьсот дней |
| 730 | Два года |
| 1000 | Тысяча дней |

Для целей 30, 60, 90 и т. д. использовать именно указанное количество завершённых дней. Календарные месяцы и годы при необходимости показывать отдельно.

### Оформление достижений

Каждая ачивка содержит:
- Уникальную тематическую иконку.
- Название.
- Описание.
- Необходимое количество дней.
- Дату получения.
- Статус «Получено» / «Закрыто».

Полученные достижения отображаются цветными, остальные — приглушёнными.

При получении достижения показывать небольшую анимацию: свечение, частицы, появление награды.

Предусмотреть экран детального просмотра достижения.

**Важно:** полученные достижения не удаляются при начале нового периода. Учитывать ачивки за лучший достигнутый период, не выдавать одну и ту же награду многократно.

## 5. Система уровней

Добавить игровые уровни, зависящие от количества завершённых дней текущего периода.

Примерная структура:

| Уровень | Название | Дней |
|---|---|---|
| 1 | Начало пути | 0–2 |
| 2 | Первые успехи | 3–6 |
| 3 | Набираешь темп | 7–13 |
| 4 | Уверенный шаг | 14–29 |
| 5 | Месяц за месяцем | 30–59 |
| 6 | Держишь курс | 60–89 |
| 7 | Новые горизонты | 90–179 |
| 8 | Большой путь | 180–364 |
| 9 | Годовой рубеж | 365–729 |
| 10 | Мастер постоянства | 730+ |

На главной странице отображать текущий уровень и шкалу прогресса.

При переходе на следующий уровень показывать поздравление.

## 6. Календарь

Создать экран календаря с помесячной навигацией.

В календаре:
- Дни завершённых периодов без алкоголя обозначать одним цветом.
- Дни вне подтверждённых периодов — нейтральным.
- Текущий день выделять рамкой.
- Дни получения ачивок отмечать небольшой иконкой.

При нажатии на день показывать его дату, статус и связанные достижения.

Не придумывать историю за даты, для которых нет сохранённых данных.

## 7. Статистика

Экран персонального прогресса.

**Основные показатели:**
- Текущий период: полных дней.
- Максимальный период: полных дней.
- Всего подтверждённых дней без алкоголя.
- Количество завершённых периодов.
- Количество открытых ачивок.
- Дата начала текущего периода.

**Визуализация:**
- Линейный график длительности периодов.
- Календарь активности.
- Карточки личных рекордов.

Не показывать медицинские результаты или улучшения здоровья как установленные факты на основании одного только счётчика дней.

## 8. Мотивирующие сообщения

Реализовать базу коротких позитивных сообщений.

Примеры:
- «Каждый день — отдельное достижение».
- «Прогресс складывается из маленьких шагов».
- «Сегодня ещё одна возможность позаботиться о себе».
- «Твой путь не определяется одним днём».
- «Ты уже прошёл немалую дистанцию».

Сообщения отображаются на главной странице и периодически меняются.

### Уведомления

Пользователь может включить:
- Ежедневное мотивирующее уведомление.
- Уведомление о новой ачивке.
- Уведомление о новом личном рекорде.

Настройка времени ежедневного уведомления.

Уведомления должны быть необязательными, ненавязчивыми и отключаемыми. Разрешение Android запрашивать только после согласия пользователя.

Содержимое уведомлений сделать нейтральным, чтобы не раскрывать личную информацию на заблокированном экране.

## 9. Дизайн приложения

**Стиль:** современный минимализм с элементами геймификации.

### Визуальные требования

- Тёмная тема по умолчанию.
- Глубокий графитовый фон.
- Контрастная типографика.
- Яркие акцентные цвета — фиолетовый, синий, бирюзовый.
- Плавные градиенты.
- Скруглённые карточки.
- Крупный центральный счётчик.
- Объёмные иллюстрации ачивок.
- Лёгкие, аккуратные анимации.
- Единый стиль иконок.

Не использовать визуальные изображения алкогольных напитков как награды.

### UX-требования

- Главная информация доступна сразу.
- Приложение не перегружено текстом.
- Основные функции доступны за 1–2 нажатия.
- Корректная работа на узких экранах.
- Поддержка увеличенного системного шрифта.
- Соблюдение системных настроек уменьшения анимаций.
- Возможность переключения между тёмной и светлой темами.

## 10. Настройки

Предусмотреть:
- Изменение даты начала или связанной с ним отметки употребления.
- Историю отметок с исправлением даты.
- Управление уведомлениями.
- Выбор светлой или тёмной темы.
- Настройку приватности уведомлений.
- Очистку всех данных с подтверждением.
- Просмотр версии приложения.
- Информацию о конфиденциальности.

Дополнительно можно реализовать блокировку приложения с помощью биометрии или системного PIN-кода.

## 11. Хранение данных

В MVP не использовать сервер и не требовать создания аккаунта.

Все данные хранить локально на устройстве.

Сохранять:
- Дату начала текущего периода.
- Историю периодов.
- Отметки употребления, их даты и связи с соседними периодами.
- Рекорды.
- Полученные достижения и даты их получения.
- Настройки приложения.
- Параметры уведомлений.

В качестве хранилища использовать Room Database и DataStore.

Не включать рекламные SDK или сторонние аналитические системы, собирающие чувствительные пользовательские данные.

После закрытия и повторного открытия приложения вся информация должна сохраняться.

Для обновления 1.0→2.0 использовать явную миграцию Room 1→2: создать пустую таблицу отметок и индексы, сохранив идентификаторы, даты и связи существующих периодов и наград. По старым промежуткам не восстанавливать предполагаемые события употребления. Имена и значения DataStore сохраняются. Разрушительная миграция с очисткой базы не допускается.

- Минимальное энергопотребление.
- Отсутствие постоянного фонового таймера.
- Пересчёт дней на основе локальных дат, а не ежесекундного обновления.

## 13. Структура экранов

Обязательные экраны MVP:

1. **Онбординг** — приветствие и выбор даты начала.
2. **Главная** — счётчик, прогресс, уровень и ближайшая ачивка.
3. **Достижения** — каталог наград.
4. **Детали достижения** — описание, условия и дата получения.
5. **Календарь** — история дней и периодов.
6. **Статистика** — основные показатели, рекорды и графики.
7. **Настройки** — персонализация.
8. **Отметка употребления** — выбор даты, предварительный расчёт и подтверждение начала следующего периода.
9. **История отметок** — список дат и исправление выбранной отметки.

## 15. Тестирование

Перед выпуском проверить:

1. Корректный подсчёт дней сразу после установки.
2. Корректное изменение счётчика после полуночи.
3. Смену месяца, года и високосный год.
4. Поведение при смене часового пояса.
5. Поведение после ручного изменения даты устройства.
6. Сохранение данных после перезапуска.
7. Корректную разблокировку достижений.
8. Отсутствие дублирующихся наград.
9. Корректность русского склонения слова «день».
10. Изменение даты начала и пересчёт статистики.
11. Создание нового периода и сохранение прежних результатов.
12. Отсутствие пересечения или повторного подсчёта дней разных периодов.
13. Работу без интернета.
14. Уведомления, включая отказ в разрешении.
15. Работу на экранах разной ширины.
16. Стабильность при длительном хранении истории.
17. Постоянную доступность кнопки «Отметить употребление» без прокрутки.
18. Отметки за сегодня, вчера и другую дату; исключение даты употребления из суммы дней.
19. Будущую дату начала после сегодняшней отметки, без преждевременного «дня 1».
20. Первый день периода, последовательные отметки и отсутствие фиктивных трезвых дней.
21. Повторную отметку той же даты, корректировку старой даты, пересечение и недопустимые даты; ошибочная операция не должна менять данные.
22. Отмену ввода и предварительный расчёт без записи реальных данных.
23. Миграцию реальной БД версии 1 с несколькими периодами, наградами и неизвестным промежутком; все прежние поля должны сохраниться, новые отметки должны отсутствовать.
24. Обновление APK 1.0→2.0 с одинаковым сертификатом, без удаления приложения и очистки данных; проверить периоды, даты наград и настройки после первого запуска.
25. Совпадение идентификатора пакета, увеличение versionCode и отказ упаковочного скрипта публиковать обновление с чужим сертификатом.

## 16. Критерии приёмки

MVP считается готовым, если:

- Пользователь может установить приложение на телефон Android.
- При первом запуске может выбрать дату начала.
- На главном экране отображается корректный счётчик.
- Данные сохраняются локально.
- Ачивки разблокируются автоматически.
- Уровни рассчитываются корректно.

- Пользователь может исправить дату отметки без потери остальных записей.

## 17. Результат разработки

Разработчик должен предоставить:

1. Полный исходный код Android-проекта.
2. Собираемый проект Android Studio.

4. Инструкцию по сборке и установке.
5. Набор тестов для расчёта дней и разблокировки ачивок.
6. Готовые экраны и графические ресурсы приложения.

**Приоритет разработки:** сначала работоспособный счётчик и надёжное хранение данных, затем достижения, календарь, статистика, уведомления и финальные визуальные эффекты.

**Итоговая цель:** создать эстетичное, простое и мотивирующее мобильное приложение, которое превращает отслеживание личного прогресса в интересный ежедневный ритуал, сохраняя уважительный и поддерживающий тон.

## 18. Выпуск и совместимое обновление 2.0

- Сохранить `applicationId = "ru.daybyday.app"`; установить `versionName = "2.0"`, `versionCode = 2`.
- Новое приложение обновляет установленную 1.0, сохраняя данные. Удалять старое приложение для установки обновления не требуется.
- Подписывать обновление тем же сертификатом, которым подписан опубликованный APK 1.0. Новосозданный debug-keystore с тем же паролем не заменяет прежний приватный ключ.
- Миграция Room сохраняет все прежние периоды, награды, даты и идентификаторы. DataStore не очищается и не переименовывается. Запуск новой версии не вызывает повторный онбординг для существующих данных.
- Старые неизвестные промежутки остаются неизвестными. Новая отметка появляется только после явного подтверждения пользователем.
- Неподписанная сборка не считается готовым устанавливаемым обновлением. Факт успешной сборки и результаты тестов должны быть отражены отдельно от факта совместимой подписи и установки.

**Состояние выпуска:** исходный приватный keystore APK 1.0 отсутствует в текущей восстановленной облачной среде. Поэтому совместимый подписанный APK 2.0 пока не опубликован. Исходники и неподписанная сборка могут быть подготовлены независимо; для выполнения критерия установки поверх старой версии нужен прежний ключ. Извлечь приватный ключ из опубликованного APK нельзя.
