# День за днём

Автономный Android-трекер дней без алкоголя. Kotlin, Jetpack Compose, MVVM,
Room, DataStore, Navigation Compose и WorkManager. Android 9 (API 28) и новее.
Интерфейс на русском, тёмная и светлая темы. Аккаунт, сервер и интернет не нужны.

В этой ветке находятся исходники версии **2.0** с фиксацией употребления
и редактируемой историей отметок.

## Состояние обновления 2.0

Готового APK 2.0 для установки поверх выпущенной версии 1.0 пока нет.
В восстановленной облачной среде отсутствует исходный файл keystore, которым
был подписан APK 1.0. Для совместимого обновления нужен именно этот приватный
ключ. Создание другого debug-keystore не заменяет его: Android проверяет подпись.

Исходники содержат миграцию Room 1→2, которая добавляет таблицу отметок,
сохраняя прежние периоды и награды. Чтобы установить обновление с сохранением
данных, должны одновременно выполняться три условия:

- Идентификатор приложения остаётся `ru.daybyday.app`.
- `versionCode` новой сборки выше прежнего: в исходниках 2.0 установлен код 2.
- APK подписан тем же сертификатом, что и установленная версия 1.0.

Старое приложение на телефоне следует сохранить установленным. Его удаление
удалит локальную историю; автоматическое облачное резервное копирование Android
для этого приложения отключено.

У стандартного debug-keystore обычно известен пароль `android`, но сам
приватный ключ создаётся отдельно для каждой среды. Он не является
общедоступным. Оригинальный keystore должен храниться вне репозитория.

## Что добавлено в исходники 2.0

На главном экране постоянно доступна второстепенная кнопка
**«Отметить употребление»** над нижней навигацией. Пользователь выбирает
сегодня, вчера или другую допустимую дату, видит предварительный расчёт
и подтверждает сохранение. До подтверждения данные не изменяются.

День употребления не засчитывается. Следующий период начинается на следующий
календарный день. Например, для даты 9 ноября 2026 года:

- Отметка за 8 ноября: новый период с 9 ноября, текущий день 1 и 0 полных дней.
- Отметка за 9 ноября: новый период с 10 ноября, 0 полных дней и подпись
  «Начало завтра». Сегодня не объявляется первым трезвым днём нового периода.

Предыдущие периоды, полученные достижения и первоначальные даты наград
сохраняются. Статистика пересчитывается по сохранённым интервалам.
Отметки отображаются в календаре и в **Настройки → История отметок**.
В истории можно исправить дату; допустимый диапазон ограничен соседними
периодами, чтобы записи не пересекались. Повторная отметка той же даты
не создаёт дубликат. Удаление всей истории остаётся отдельным действием
**«Удалить все данные»** с подтверждением.

## Сборка в Android Studio

1. Откройте корень проекта в Android Studio с поддержкой AGP 8.9.2.
2. Выберите JDK 17 и установите Android SDK Platform 35 и Build Tools 35.0.0.
3. Дождитесь Gradle Sync и запустите конфигурацию `app` на тестовом устройстве API 28+.

В терминале с настроенными `ANDROID_HOME` и JDK 17:

```bash
./gradlew assembleDebug testDebugUnitTest lintDebug
./gradlew assembleRelease
```

Отладочный APK: `app/build/outputs/apk/debug/app-debug.apk`.
Неподписанный компактный APK: `app/build/outputs/apk/release/app-release-unsigned.apk`.
Отладочная сборка с новым локальным ключом предназначена для отдельного
тестового устройства; она не гарантирует обновление установленного APK 1.0.

В подготовленной облачной среде:

```bash
bash scripts/package-test-apk.sh --unsigned
```

Команда создаёт `/workspace/artifacts/day-by-day-2.0-unsigned.apk` с R8
и удалением неиспользуемых ресурсов. Неподписанный APK нельзя установить
на телефон или использовать для обновления.

Если исходный keystore восстановлен:

```bash
DAY_BY_DAY_KEYSTORE=/secure/path/original-debug.keystore bash scripts/package-test-apk.sh
```

Скрипт рассчитан на исходный debug-keystore со стандартным паролем `android`.
Перед созданием файла `/workspace/artifacts/day-by-day-2.0.apk` он сравнивает
сертификат с опубликованным `downloads/day-by-day-1.0.apk`. При отсутствии ключа или несовпадении подписи
подписанное обновление не создаётся. По умолчанию путь к ключу —
`$ANDROID_USER_HOME/debug.keystore`.

## Проверки

```bash
./gradlew testDebugUnitTest lintDebug
./gradlew connectedDebugAndroidTest
```

Инструментальные тесты используют и очищают данные приложения. Запускайте их
на отдельном тестовом устройстве или эмуляторе, а не на личной установке
с историей пользователя. В набор входят проверки миграции существующей БД,
дней употребления, редактирования и сохранения прежних результатов.
Результаты конкретных запусков приведены в [docs/validation.md](docs/validation.md).
Наличие команды или теста в проекте само по себе не означает успешное выполнение.

## Codex cloud

Среда каждой задачи уже изолирована: используйте существующий checkout,
не создавайте дополнительные Git worktree без явного запроса пользователя.

```bash
cd /workspace/without_alcohol
bash scripts/setup-cloud.sh
source scripts/cloud-env.sh
./gradlew assembleDebug testDebugUnitTest lintDebug
```

Скрипт хранит SDK, JDK и кеши в `/workspace`, проверяет контрольные суммы
инструментов и сохраняет TLS-проверку. Для установки зависимостей и сборки
без подписи приватные сервисы и секреты не требуются. Подпись совместимого
обновления требует доступа к исходному keystore, описанному выше.
Для первоначальной загрузки нужны разрешённые домены `github.com`,
`release-assets.githubusercontent.com`, `services.gradle.org`, `dl.google.com`,
`repo.maven.apache.org`, `plugins.gradle.org` и `plugins-artifacts.gradle.org`
(покрываются предустановкой менеджеров пакетов).

Опционально `WITH_EMULATOR=1 bash scripts/setup-cloud.sh` установит эмулятор
и образ API 28 для проверки минимальной версии. На Linux без `/dev/kvm` можно
использовать `-accel off`; программная эмуляция заметно медленнее.
ADB требует доступный для записи служебный каталог пользователя `.android`.

## Данные и структура

- `domain/`: независимые от Android расчёты дат, уровней, наград и отметок.
- `data/`: Room для периодов, наград и отметок; DataStore для настроек.
  Миграция 1→2 сохраняет прежние строки и создаёт пустой журнал отметок.
- `ui/`: Compose, навигация, исходные экраны и формы записи/исправления отметок.
- `notifications/`: необязательные нейтральные уведомления через WorkManager.
- `TrackerViewModel`: состояние, предварительный расчёт без записи в БД,
  сохранение и обновление календарной даты.

Старые промежутки между периодами при миграции остаются неизвестными:
приложение не считает их автоматически днями употребления. Внутренние
нулевые периоды могут связывать последовательные отметки, но не добавляют
трезвые дни, завершённые периоды или точки истории в интерфейсе.

В день начала крупный счётчик показывает 0 полных дней, а текущий день — 1.
До наступления будущей даты начала показаны 0 полных дней и дата начала.
Пересечение периодов и повторный подсчёт дней запрещены. При переводе часов
назад счётчик не становится отрицательным, сохранённые награды не исчезают.
Сегодняшний день не считается полным. Первоначальные даты полученных наград
сохраняются при записи употребления и исправлении его даты.

Разрешение уведомлений запрашивается после включения соответствующей
настройки. При отказе приложение продолжает работать. По умолчанию уведомления
отключены, текст нейтрален; приватный режим скрывает подробности на экране
блокировки. WorkManager соблюдает ограничения энергосбережения Android,
поэтому доставка может произойти позже выбранного времени.
Постоянного фонового таймера нет. Приложение не запрашивает `INTERNET`,
не содержит рекламы и аналитики и не делает медицинских выводов из числа дней.
